## 新增：池订阅顺序调整功能（全局统一 + 上下箭头）

用户诉求：池订阅（不同 API 的外层订阅）顺序无法事后调整，只能靠"先加谁后加谁"间接决定。

实现（无数据库迁移）：
- 全局顺序**不单独存储**，等价于 5 个能力模型 `subscription_ids`（即 `virtual_model_bindings.position`）的合并顺序。备份会带上绑定顺序，天然持久化。
- 后端 `src-tauri/src/commands/virtual_models.rs`：
  - `list_pool_subscription_order`：按 `POOL_ORDER_READ_ORDER = [Llm, Vision, Multimodal, Speech, Embedding]` 首次出现收集，得到展示顺序。
  - `reorder_pool_subscriptions(order)`：对每个 `paradigm()==Pool` 的能力模型，仅重排已绑定成员（`reorder_by_rank` 稳定排序，未知 id 落末尾），`save_bindings` 落库 + 内存更新 + `last_used_index=0`。
  - 纯函数 `reorder_by_rank` + 3 个单元测试（`pool_order_tests`）。
  - `lib.rs` 注册两个命令；`proxy/web/api.rs` 的 `web_commands!` 同步加两条（网页/TUI 通道）。
- 前端：
  - `src/api/tauri.ts`：`listPoolSubscriptionOrder` / `reorderPoolSubscriptions`。
  - `src/routes/Pool.tsx`：矩阵下方新增「订阅顺序」卡片，行 = 真正绑定的池订阅，↑/↓ 换位即调 `reorder_pool_subscriptions` 并失效 `["pool-sub-order"]` + `VIRTUAL_MODELS_KEY`。只显示会参与路由的成员（避免"仅禁用条目的订阅"移动后被回滚）。
  - 四语言新增 `pool.order.title/subtitle/empty/hint/moveUp/moveDown`（各 1333 键，零缺失）。

验证：`cargo check --lib` 通过（3 个既有 warning）；`cargo test --lib pool_order_tests` 3/3 通过（总 1047）；`npx tsc --noEmit` 通过。

关键点回顾（本轮讨论）：外层订阅顺序由每个 `model-*` 的 `RoutingMode` 决定（默认 Sequential=绑定顺序，非轮询）；"不可调度"判定含 disabled/非 Healthy/冷却中/token 额度超限。池（chain）模式失败降序只降**模型**不降**订阅**，订阅靠状态机被跳过。

## 修复：ModelPoolPicker 模型名无法自由输入

根因：`EntryRow` 在「模型发现列表非空」时渲染 Radix `<Select>`，而 Radix Select 不支持自由文本（placeholder 写着"选择或输入"但实际输不了）；「手动输入」建的空行也因列表存在而仍是下拉。

修复：新增 `ModelNameCombobox`（`src/components/ModelPoolPicker.tsx` 末尾）——
- 永远渲染 `<input>`，可自由输入任意模型名；发现列表降级为建议。
- 建议列表**行内绝对定位**（不 portal）：因为 `DialogContent` 是 `overflow-y-auto` 模态层，portal 到 body 会被裁剪且被 Radix 判定"点击外部"关闭弹窗。
- 支持 ↑/↓ 选择、Enter 确认、Esc 关闭、点击外部关闭；`dirty` 标记让"聚焦展示全部、输入才过滤"。
- 主题变量用 `--surface / --line-2 / --surface-2 / --ink`（`--border-2`、`--bg-elev` 在本项目未定义，别用）。
- 移除 `Select` 相关 import（tsconfig `noUnusedLocals: true`）。

验证：`npx tsc --noEmit` 通过；`npm run check:i18n` 全部通过。
